# PhilthySports / PhilthyParleys project evidence consolidation

Prepared 2026-10-07 UTC. This document consolidates the useful, non-secret project evidence accumulated across prior PhilthySports / PhilthyParleys audits, validation reports, GitHub work, Render work, MCP work, Android build evidence, and historical-model research.

This is an evidence archive and operating map, **not** a claim that every production gate is currently passing. Current truth must come from the repository workflows and deployed status endpoints.

## Merge policy

The public repository keeps implementation source, governance rules, non-secret evidence summaries, checksums, reproducible commands, skill definitions, and CI workflows.

The following are intentionally **not** copied into public source:

- API keys, access tokens, service-account private keys, signing private keys, passwords or provider credentials;
- private Google Drive identifiers or links that are not required for public reproducibility;
- private incident evidence that would disclose credential-bearing file locations beyond the already-sanitized audit descriptions;
- APK/ZIP/tar binaries that are already reproducibly generated by GitHub Actions;
- legacy serialized models whose training contract/provenance is unverified;
- synthetic/random notebook output presented as training evidence.

Where a sensitive or binary artifact matters, preserve a hash, source commit, workflow run, or redacted evidence record instead of copying the secret/binary into git.

## Governing protocol retained

The project follows the evidence-first operating rule established in the historical Master Protocol:

**Understand → Decompose → Inspect → Map → Challenge → Plan → Act → Verify → Recalibrate → Explain → Retain → Improve**

and the nested experiment loop:

**Evidence → Hypothesis → Smallest Experiment → Result → Update → Regression Check**

Key invariants retained in current code and skills:

1. Evidence controls promotion.
2. Predictive features require `as_of < event_time`.
3. Outcomes/settlement must not leak into pregame features.
4. Missing evidence is a blocker, not a value to infer or fabricate.
5. Provider configuration is not the same as successful fresh credentialed proof.
6. Each sport is promoted independently.
7. Market baseline remains active until the relevant strict model gate passes.
8. Mock/sample/test data must never silently replace production evidence.
9. Emulator evidence is not physical-device evidence.
10. PhilthySports is decision support; no automatic wagering or DFS contest entry is authorized.

## Historical data and model governance

### Strict policy

The current strict trainer preserves:

- chronological folds;
- in-fold preprocessing;
- OOF-only calibration;
- untouched chronological holdout;
- leakage checks;
- schema/provenance/checksum checks;
- portable inference parity;
- explicit source quarantine holds;
- Brier improvement relative to the same market baseline;
- non-inferior log loss;
- ECE maximum `0.01`;
- sport-specific sample minimums.

Current sample policy:

| Sport | Total | OOF | Holdout |
| --- | ---: | ---: | ---: |
| NFL | 1,200 | 600 | 240 |
| NBA | 2,500 | 1,200 | 500 |
| MLB | 4,000 | 2,000 | 800 |
| NHL | 2,500 | 1,200 | 500 |

Meeting the row count alone does not authorize promotion.

### NFL archive recovery

`backend/training/nflverse_archive_backfill.py` and `backend/training/NFL_ARCHIVE_RESEARCH.md` preserve the separate NFL archive research path.

The recovered research corpus produced 1,596 rows across 2020–2025 from 149 pinned snapshots, with 1,023 OOF rows and 321 final holdout rows. The candidate was correctly rejected:

| Metric | Candidate | Market / limit | Result |
| --- | ---: | ---: | --- |
| Brier | 0.212071438 | market 0.211269473 | FAIL |
| Log loss | 0.611067451 | market 0.608803910 | FAIL |
| ECE | 0.081047059 | <= 0.01 | FAIL |
| Portable parity max abs error | 2.220446049250313e-16 | <= 1e-10 | PASS |

The source also remains research-only because Git committer timestamps are not independently witnessed sportsbook quote-publication receipts. `strict_promote.py` now honors explicit source quarantine flags so a numerically strong candidate cannot bypass a source hold.

Do not tune against the exposed NFL holdout. Any future NFL candidate needs a newly predeclared untouched chronological evaluation window.

### NBA / MLB / NHL next evidence contract

For each sport, admissible historical backfill must retain stable event mapping, immutable raw evidence, a pregame snapshot time, an independently observed final/result availability time, and source hashes.

Special cases retained from the audits:

- NBA: competition scope and overtime-inclusive final-result convention must be explicit.
- MLB: doubleheaders require game-specific IDs/start times; day/team-only joins are rejected.
- NHL: regulation vs full-game/OT/shootout settlement scope must match the market being modeled.

The repository includes `backend/training/odds_api_historical_backfill.py`, historical-source/recovery helpers and `historical-access-probe.yml`. Historical provider access, when available, is not permission to fabricate timestamps or bypass the normal canonical-evidence checks.

## Provider credential / live-proof boundary

Historical audits found legacy credential-bearing material outside the active secure source. The required remediation remains:

1. revoke/rotate exposed legacy provider credentials at their issuers;
2. remove broad public/link sharing from secret-bearing legacy storage;
3. issue fresh scoped credentials only for integrations still required;
4. store fresh values only in protected backend environment/secret storage;
5. prove fresh credentials with safe server-side canaries;
6. prove retired credentials are inactive through issuer records or a documented safe rejection check;
7. never commit or expose the new values.

The repository contains `live-provider-proof.yml` and provider-canary workflows. Their evidence must distinguish:

- key configured;
- credentialed request actually succeeded;
- schema/freshness passed;
- quota/rate-limit state;
- old credential independently proven revoked.

A successful keyless fallback does not count as successful credentialed-provider proof.

## Physical-phone acceptance

A real-device pass requires the exact signed APK and `--require-physical`. The report should retain:

- APK SHA-256;
- physical-device detection;
- install result;
- launch/process result;
- backend connection result;
- four-sport navigation/feed evidence;
- Picks/Parlay/Settings/Evidence route checks;
- screenshot and crash/error log evidence.

The phone-only Termux/Wireless-ADB helper exists because a separate computer is not required. Device identifiers, IMEI, phone number, EID, MAC addresses and pairing codes must not be committed as evidence.

## Legacy notebook/data quarantine

Old BetP/TILT notebooks and exports are useful architectural/reference material but must not become promotion-grade evidence merely because they contain predictions or model code.

In particular, legacy notebooks that generate features/probabilities with random or synthetic values remain excluded from canonical training. Legacy `.joblib` files are not executed or promoted unless their feature contract, training lineage, target, preprocessing, calibration and evaluation evidence can be reproduced.
